# NS-09 history implementation plan

> **For agentic workers:** use superpowers:test-driven-development; bounded disjoint slices within this NS may run in parallel. Parent integrates and performs whole-branch review.

**Goal:** Implement the accepted NS09 history/window design in both native app and panel.
**Architecture:** Optional `history: {version:1,providers,days:{date,provider,aggregate}[]}` in existing snapshot, computed from existing daily report. Pure projections select a provider/date range; native and panel keep independent history filters.
**Tech Stack:** TypeScript/Bun/React; Swift6/SwiftUI/AppKit.
**Spec:** `docs/superpowers/specs/2026-10-20-ns09-usage-history-window-design.md`.

## Constraints / rulings
- User requested sequential execution of NS07..12 after receiving NS09 written spec; treat this as approval to execute its scope, not permission to publish/merge.
- Native opens one retained window, shares snapshot and refresh callback; no new scanner.
- No lifetime session attribution; no export until NS10; preserve EN/VI/zh, unknown/partial and schema1 legacy.
- Custom dates inclusive, reject future/end-before-start; presets evaluated in snapshot timezone using calendar arithmetic.
- Any implementation detail changed from spec is recorded below with its reason.
