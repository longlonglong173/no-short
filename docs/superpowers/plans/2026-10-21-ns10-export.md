# NS10 safe export plan

> **For agentic workers:** TDD, disjoint engine/native/UI slices; one reviewed PR after integration.

**Goal:** Export the selected history range/provider to CSV/JSON from both UIs.
**Architecture:** Pure serializers consume the same NS09 projection; native Save dialog and panel Blob download freeze the payload on explicit click. Never read messages or rescan logs.
**Tech Stack:** TypeScript/Bun, React, Swift/Foundation/AppKit.
**Spec:** `docs/BACKLOG.md#ns-10` and NS09 history/window design.

## Ruling: session identifier provenance
Daily aggregates cannot attribute usage to sessions. Optional identifiers must therefore be a separate `sessionReferences` section: only sessions whose lastActivity falls in the selected calendar range and provider, labeled `last-activity-in-range-not-cost-attribution`. No lifetime session costs/tokens are exported there. This is a reference list, not a complete set of contributing sessions. Missing/invalid lastActivity is excluded. Default is no identifiers, titles or references. UI checkbox explains this scope explicitly.

## Contract
`createUsageExport(snapshot,provider,start,end,{includeSessionIdentifiers?:boolean})` returns `UsageExport|null`; `serializeUsageExport(document,format:'csv'|'json'):string` in TS `src/export.ts`.
Document: `formatVersion:1,costBasis:'api-equivalent-estimate-not-billing',provider,start,end,timeZone,generatedAt,status,aggregate,days` plus optional `sessionReferences:{scope:'last-activity-in-range-not-cost-attribution',items:[{id,title,provider,lastActivity}]}`. aggregate/days use NS09 objects. No paths/conversations or session costs. CSV rows have recordType,scope,date,provider,model,token fields,amountUSD,knownCostUSD,pricingStatus,timezone/start/end/generatedAt/status and optional sessionId/sessionTitle/lastActivity columns only when enabled. CSV text cells quoted and formula-prefixed when unsafe (`=+-@` after whitespace); numbers remain numeric and unknown amount is blank, not zero.
