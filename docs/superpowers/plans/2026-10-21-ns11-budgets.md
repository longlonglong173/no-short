# NS11 budget implementation plan

Goal: opt-in daily/monthly API-equivalent USD budgets for All/Codex/Claude. Native app only (system notifications and local settings); no new scanner, billing/quota promises, server or account access.

- Default all limits off (nil), notifications off. Valid finite positive USD thresholds; empty removes that limit. Persist rules per provider and notification opt-in locally.
- One retained settings window accessed from popover gear/right-click. Save validates before applying; cancel never changes rules. Provider-specific daily and monthly fields, explicit opt-in for OS banners. Request notification permission only from explicit enabling action, not normal launch/refresh.
- Pure UsageCore budget evaluator consumes existing today/month provider aggregates, not lifetime sessions or history filters. All uses combined totals. LegacyCodex fallback only if noClaude metadata/mixedbreakdowns; missingprovideraggregate unavailable, never borrowed.
- Reject stale/error snapshots or wrong current local date; notification read failures do not hide usage errors. Full price within/over shows estimate only. Partial has known lower bound, never precise remaining; trigger only if lower bound already exceeds threshold. Unknown or partial-below-limit never reported safely within budget.
- Persistent tracker once per source/timezone/provider/period/calendar date-month; repeated refresh, restart, toggling/threshold changes do not re-notify in same period after an alert. New day/month rearms naturally. Missing/stale/unknown data never rearms. Bound old tracker entries, do not store session titles/messages.
- In-app budget status always visible for configured budgets independently of OS permission/latch. Optional OS events reuse notification center service, no new delegate. Failure/denial is localized and in-app remains usable.
