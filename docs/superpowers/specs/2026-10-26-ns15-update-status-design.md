# NS-15 — visible version and quiet daily update checks

User requested a sensible update status in the main native app and a real0.6.1 release to test from0.6.0; explicitly selected automatic daily checks with in-app notices only. UX details are delegated to the implementer; continue the established inline workflow.

- Always show the running bundle version and a compact update row at the bottom of the main popover, including session/model/setup views. States: not checked, checking, newer version available, no newer release found, downloading/installing and retryable failure. Show the last successful check time. Never infer “current” before a verified result, or from a failed request.
- Reuse the existing retained coordinator for popover, About and menu. Show a nonmodal new-version notice and explicit update button; manual action opens the existing standard Sparkle confirmation flow. Retain the known newer version after cancelling/closing the installer UI. Distinguish usage-data refresh wording from app updates.
- Probe via pinned Sparkle2.10.0 `checkForUpdateInformation`, not a second GitHub/network client or background installer. Scheduler/library automatic checking stays disabled; app-owned scheduling does one probe at startup after10s and hourly due checks/wake/panel-open, with at least86400s between attempts across restarts. Manual checks bypass cadence. No download, popup, OS notification or installation from probes.
- Save only attempt/success timestamps and validated latest version, scoped to the canonical feed/public-key identity. Cache is a display hint; all installs recheck signatures through Sparkle. Honor the user-facing “Check daily” toggle (on by default for this approved change). Manual checks work when it is off. Skip while terminating, asleep, busy or maintaining cache; malformed/future dates recover safely.
- Keep archive/feed verification, canonical URL delegate, ARM policy, profiling/JavaScript/download/auto-install off and existing shutdown drain. Keep EN/VI/zh-CN, macOS14+, schema v1 and ccusage20.0.34. No replacement of the user's running installation.
- Alternatives: About-only leaves the version hidden; enabling Sparkle background checks can introduce SDK reminders. Chosen: shared main-popover status and informational probes, so discovery stays quiet and installation remains explicit.
- Release0.6.1 with the existing owner key, immutable new tag/assets and assets-first feed/website rollout through PRs. Users on0.6.0 test by manually choosing Check for Updates; the daily UI arrives with0.6.1. Do not retrofit0.5.0 or publish a dummy0.6.2.
