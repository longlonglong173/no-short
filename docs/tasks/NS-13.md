# NS-13 — Project and explicit work grouping

## Design locked before implementation

Two independently verifiable milestones: project allocation; explicit parent/child work rollup. All temporal totals consume NS-18 canonical session/day contributions, never lifetime session totals or last activity. Filtering uses the same provider, calendar range and snapshot timezone as History. Each ledger row contributes once to project totals and once to one work root. Missing attribution remains visible as unallocated usage.

Optional `SessionUsage.grouping` stores only an opaque project ID, basename label, source/confidence, explicit parent sessionKey, and conflict flags. Codex reads only `session_meta.payload.cwd` and `source.subagent.thread_spawn.parent_thread_id`; no message/title/time inference. A bounded read-only Git query resolves the current common directory; existing non-Git directories receive recorded-directory identity; missing/deleted directories remain unknown. Cached cwd is private local metadata, resolved afresh so deleted or renamed directories cannot be falsely reused. Claude can use an explicit first-record cwd but no parent relation is invented from agent filenames or conversation messages.

Ledger identity is the exact snapshot session ID. Parent references resolve provider plus explicit sessionKey to that ID. Cross-provider joins are forbidden. Conflicting duplicate metadata, self edges, cycles and missing parents stay separate with a notice. Children of an unresolved node are also kept separate, preventing an ambiguous tree from looking verified. Normal main sessions without lineage are independent work roots. A root with no own in-range rows still holds its in-range descendants. Rollups sum direct canonical ledger rows, never parent lifetime/session totals. Models retain pricing provenance, partial and unknown costs.

Existing exports keep their privacy behavior. A grouped export is explicitly selected and includes safe project labels and source/confidence; work/session identifiers require the existing identifier opt-in. Absolute cwd/project paths are never exported. Invalid optional grouping must not invalidate a valid schema-1 dashboard.

## Implemented metadata evidence and limits

Read-only first-record shape verification on 2026-10-27 sampled 17 current Codex `session_meta` records. All had `cwd`, `id`, `source`, and `thread_source`; 16 had object `source` with explicit `subagent.thread_spawn.parent_thread_id`; one had string source. Only allowlisted field-presence counts and types were printed. No message, absolute path, title, session identifier, settings, or key was printed or changed. `forked_from_id` is deliberately not interpreted as parent lineage.

Git resolution is one bounded `rev-parse` per unique cwd per provider scan, memoized for that scan; 1-second timeout, 16 KiB output cap, no shell, no optional locks, and inherited Git directory overrides removed. The result describes **current** Git common-directory identity, not historical repository membership. Linked worktrees share the common-directory hash. Existing non-Git directories have lower-confidence recorded-directory hashes. A renamed/deleted recorded cwd is unknown on the next scan. Labels are basenames, never absolute paths. Hashes do not expose the raw path. Claude project grouping requires an explicit cwd on the first record; later-message cwd and encoded project directories are not inferred. No Claude parent lineage is produced.

History grouping is opt-in. Unknown project usage remains in its own visible bucket. Work rows show direct selected-range tokens/cost plus model tokens/cost, while the root total sums descendants exactly once. Invalid graph components remain independent with a notice. A metadata-only root may have zero direct usage while its descendant contributes in-range usage.

Exports remain formatVersion 1. Default ungrouped output is unchanged. Selecting project/work mode adds a `grouping` extension and explicit CSV group-rollup/model rows. Names/IDs and direct session/model rows are added only with the existing session-identifier opt-in. A work label defaults to `Work N`; project labels, source and confidence are safe metadata. Missing exact ledger disables grouped export; ordinary daily export remains available.

NS-18 exposes `reconciled` plus optional `reconciliationIssue`. Token mismatch shows unallocated-usage notice. An inherited mixed fallback/genuine-price daily boundary may preserve exact tokens and useful per-session known costs while daily and session price bases differ; this is shown as **pricing uncertainty**, with the reason retained in grouped JSON. Neither is called a verified reconciliation. Custom model rates/provenance and unknown/partial semantics remain attached to aggregates.

## Acceptance boundaries

Both milestones are implemented and locally verified. Grouping mode changes presentation/export breakdown, while provider and date controls define the scope for History, comparison, and grouped export. No project-specific filter was added; dashboard live pin/today/month behavior remains globally scoped. A token reconciliation failure hides unreliable grouped rows and disables grouped export; pricing-only uncertainty keeps useful exact-token rows with a clear cost notice/reason. Graph rollups rely on NS-20/NS-18 canonical contributions; they never sum lifetime parent totals with child totals.

Project assignment describes recorded initial cwd resolved to current directory/Git identity; it does not attribute work to every file/tool action within a session. Claude later-record cwd or parent lineage is intentionally unavailable. Missing metadata is never guessed. Export JSON and CSV retain reconciliation reason, pricing provenance and unknown/partial status. No absolute cwd/project path is added to snapshots, MCP or exports. Existing optional explicit identifier export retains its prior privacy contract.

No deployment, public artifact, installed-app smoke, clean-machine proof, user acceptance, notarization, settings mutation, BACKLOG edit, push, PR or merge is claimed. Root owns independent review and publication of the task branch; the user owns merges.

## Independent review fixes

The independent review identified two P2 issues, reproduced with failing regressions in both TS and Swift before the fixes:

- All-provider work CSV rollups/model rows used the document's `all` provider despite a known work provider. Group records now use the known group provider; project aggregates that combine providers keep the document provider. Tests cover all-provider export with session identifiers disabled and verify that no private titles/identifier columns appear.
- Duplicate parent metadata compared raw UUID spelling even though graph resolution already treated UUID keys case-insensitively. Merge and graph resolution now share UUID-only canonicalization. Equivalent uppercase/lowercase UUID parents retain the explicit 9-token multilevel work; arbitrary non-UUID parent identifiers remain case-sensitive and genuinely different parents still conflict.

The combined all-six review found that an **open** work-group table at 360px widened the document to 600px: the `.history-grouping` grid item's automatic minimum width propagated its 580px inner table to the page. The existing language/width check had changed provider first, closing the details and missing this state.
