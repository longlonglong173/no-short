# NS-18 — Exact session/day drilldown

Design: retain schema-v1 and extend optional history with sessionDays rows `{date, provider, sessionId, aggregate}`. Rows come from the same canonical loaded/deduplicated Codex and Claude events as daily and session totals, using the selected timezone. Group event references once by day/session; no per-session filesystem scan. Serialize unified ledger in ccusage-adapter-all/src/report.rs, preserve explicit Codex fallback provenance, and project each row through the shared pricing adapter. IDs use the exact public session ID including Claude prefix.

Capability: absent or malformed optional ledger leaves daily history available. An explicit empty array is supported empty. Validate day/provider/session keys and reconcile token classes, model totals, known cost and uncertainty per day before presenting allocation. Mismatch is visible and the UI does not claim reconciled session totals. Last activity and lifetime costs are never used for day attribution. Opening local details does not mutate pinned/follow selection.

Public TS: `sessionUsageForRange(snapshot: UsageSnapshot, provider: 'all' | UsageProvider, start: string, end: string): SessionUsageRange | null`. Result: `{sessions: {sessionId, provider, aggregate}[], aggregate, reconciled}`. Swift: `UsageHistory.sessionUsageForRange(_ snapshot: UsageSnapshot, provider: String, range: UsageHistoryRange) -> SessionUsageRange?` with corresponding fields. Null/nil is unsupported/unavailable. Range is inclusive calendar days in snapshot timezone. Unknown and partial pricing survive aggregation.

Exports keep their current scope and default privacy. No ledger/session IDs or names are added to default CSV/JSON. Existing opt-in lastActivity references remain explicitly labelled references, not attribution.

Verification results are recorded in the task report. This source change does not publish or install a release, modify real logs/settings, or prove Intel execution/installed-app behavior.

## Result and reconciliation

Implemented in native History and React. Select a day, review contributing sessions and open a session's exact day-scoped model/token/cost details. These are window/panel-local selections and do not change pins, following, provider context or trigger scans. Read-only helpers also support arbitrary inclusive day ranges.

`SessionUsageRange.reconciliationIssue` is optional in TS (`'tokens' | 'pricing'`) and nullable `String` in Swift. Token mismatch hides unreliable allocation behind an explicit warning. Price-only mismatch keeps valid session rows and known price portions visible with an incomplete-pricing warning. This intentionally preserves NS-16's conservative mixed-fallback daily semantics: a daily model merged from fallback and genuine sessions excludes that whole model's cost, while a genuine individual session still has a defensible known amount. The ledger retains it, sets `reconciled=false, reconciliationIssue='pricing'`, and never calls the sum an exact daily cost. A matching custom override prices all portions and restores reconciliation. Unknown remains unknown, never a priced zero.

The extended reader revision is `ns20-session-scope-v2-ns16-pricing-provenance-v1-ns18-session-days-v1`. The combined verified patch keeps NS-20/16 hunks unchanged as its prefix and appends the session/day extension. It uses the same canonical representative map, replay/response dedup, timezone, row serializer and explicit model fallback boolean for daily and ledger rows. The service's revision-scoped cache automatically invalidates older reader output. Legacy reports without the optional ledger retain working daily history and receive a localized detail capability notice.

## Independent review follow-up: native reference lookup

The review measured a main-thread stall from checking every retained ledger row with a linear lifetime-session search. Reference validation now builds one Set keyed by provider and exact public snapshot session ID per helper call, then checks membership. This changes lookup work from quadratic to linear in sessions plus ledger rows, without caching or changing attribution/reconciliation.

The same optimized reviewer driver, decoding excluded, measured 1k sessions/3k rows: 6.9 → 1.7 ms; 5k/15k: 138.8 → 9.1 ms; 10k/30k: 563.8 → 16.3 ms. These are local synthetic measurements, not a timing test or production guarantee. Six focused native tests passed, including new missing-reference, cross-provider-reference and equal-ID/different-provider cases. Rust, React, source patch and public interfaces are unchanged.
