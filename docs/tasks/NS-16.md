# NS-16 — Price origins and local custom pricing

This task adds optional pricing metadata to schema-v1 snapshots and a native **Pricing…** editor. It depends on NS-20 source-build support (PR #40); the NS-16 PR must be merged after that prerequisite. It does not change the app version, publish a release, install an app, or modify provider settings/logs.

## Behavior and data flow

- Overrides live in `~/Library/Application Support/no-short/usage/pricing.json`, shared by the native worker and MCP engine. `NO_SHORT_USAGE_PRICING_FILE` selects an isolated configuration file for development/tests; `ServiceOptions.pricingFile` provides the equivalent injected path.
- Configuration version 1 contains an optional `updatedAt` (configuration save time) and up to 512 overrides. Each override identifies an exact `codex`/`claude` provider and model name, with finite nonnegative `input`, `output`, `cacheRead` and `cacheWrite` USD rates per million tokens. Duplicate provider/model pairs, blank/control-character model names, oversized files and symlinked/nonregular configuration files are rejected.
- No aliases are guessed. Explicit zero rates mean a priced zero; an absent override uses ccusage. The native editor supports Add, per-model restore, Restore defaults, Save and Cancel. Restore changes only the draft until Save. An unreadable/invalid configuration remains untouched until an explicit Restore defaults + Save; errors remain visible.
- The engine reads configuration on every request, including requests that could return a fresh cached snapshot. A validated-configuration fingerprint invalidates cached prices after save/reset, without changing log-source scope. A price change during a scan prevents publishing an apparently current result using the old rates. Invalid/unreadable configuration returns an explicit warning; retained data keeps its previous labelled pricing basis.
- Prices are applied once in the shared adapter to each provider/model's session and daily usage. Today/month/chart/history and exports therefore use the same projection. Custom rates reprice retained history using the current configuration; they do not reconstruct prices effective at historical request time.
- Partially unpriced model groups retain positive known recorded costs as partial lower bounds, even when an unrelated model is repriced. Fallback estimates are excluded separately; a custom override can price the entire group.
- A controlled pinned-CLI probe confirmed Codex raw input 100/cache 50/output 10 becomes report input 50/cacheRead 50/output 10/total 110. The four report token classes are disjoint; custom pricing does not charge cached input twice.

## Verified reader provenance

The published upstream 20.0.34 unified report omits fallback attribution even though focused Codex reports expose it. NS-16 extends NS-20's verified source patch, preserving its session identity/toolchain fixes, to emit explicit `isFallback: true | false` on every Codex model breakdown and OR fallback state through unified aggregation. Other providers omit that field. The locked patch revision is `ns20-session-scope-v2-ns16-pricing-provenance-v1`; changing it also changes the cache scope.

The raw report boundary rejects nonempty Codex data without an explicit boolean and shows a localized update-runtime message. Empty sources remain valid, and legacy schema-v1 snapshot decoding remains supported. No model names are guessed and no extra focused reports/scans are added. Real-CLI regression covers absent model metadata and explicitly genuine `gpt-5` in the same production command, plus mixed daily aggregation and a custom override.

This requires a future rebuilt bundle containing the patched reader; pairing the new helper with the unchanged published upstream reader is deliberately unsupported. App/version/release assets are not overwritten by this source task.

## Interfaces and provenance

- `ModelUsage.pricing?` carries source (`ccusage`, `custom`, `fallback`, `unpriced`, or `mixed`), optional provider, optional configuration save timestamp and optional custom unit rates.
- `UsageSnapshot.pricing?` carries `basis` (`ccusage-report` or `current-custom-rates`), `configurationRevision` and optional configuration save timestamp. Raw `pricingSource: online | cached` remains intact.
- ccusage exposes calculated costs without reliable unit rates/effective dates in this report. The UI says those values are unavailable rather than inventing them. A fallback price is labelled unverified and excluded from known costs until an explicit custom override supplies a basis.
- TS/Swift history aggregation preserves matching metadata and marks mixed origins without claiming one rate. Legacy snapshots without metadata remain valid. React shows read-only provenance/rates and historical repricing labels; configuration editing stays in the native app.
- JSON exports preserve the optional pricing extension. CSV adds pricing basis/origin/configuration timestamp and four unit-rate columns when the snapshot has pricing metadata. Legacy snapshots retain the original column set. Unknown amounts remain null/blank and existing CSV formula protection remains in effect.
- Native controls, model details, history and React labels support English, Vietnamese and Simplified Chinese. All amounts remain API-equivalent estimates, not subscription invoices or quota.

## Verification

The task report in the controller's temporary workspace records exact commands, RED/GREEN output and final suite results. Tests use isolated synthetic logs/configuration and local fixture rendering.

- Pricing regressions cover exact provider/model matching, explicit zero, save/reset invalidation, config corruption, duplicate/invalid rows, fallback uncertainty, export metadata and configuration changes during a scan.
- Native tests cover persistent validation/permissions, symlink refusal, save/cancel/reset behavior, malformed configuration, legacy decoding, history/export provenance and compact editor rendering in all three languages/themes.
- Final stacked verification after independent-review fixes: 165 Usage tests (no skips), 204 Swift tests, 19 native script tests and 33 browser tests passed; TypeScript, UI build, repository validation and `git diff --check` passed.
- Browser tests cover the shared projection and provenance in History, language changes and a compact 360-pixel view. Offscreen native fixture renders at 440 points and the compact panel screenshot were inspected.
- Device/host acceptance remains separate: this does not verify installed-app menu clicks, live Codex-host delivery, VoiceOver, clean-machine installation or Intel execution. Existing baseline Swift sendable-capture and Vite legacy-import warnings are not hidden by this task.

The initial concurrent all-Usage run hit two unchanged launcher-test 5-second timeouts. A focused launcher rerun passed, followed by the full unmodified suite under the shared heavy-process lock: 152 passed, no failures or skips. No launcher code or timeout was changed. A locally compiled source helper was used to enable the initial slow-pipe regression. After the review fixes, both architectures were rebuilt from the verified source patch and the complete suite used those readers. Generated runtime hashes are saved separately from the immutable published manifest.

Independent review reproduced two real defects in the initial implementation: the production unified report omitted the injected test-only fallback field, and custom repricing could erase positive known portions of partially unpriced model groups. Both were fixed with RED→GREEN regressions. Source-built ARM and Intel readers passed build/signature checks with the extended verified patch; the final suite uses the actual rebuilt reader, not invented provenance fields.
