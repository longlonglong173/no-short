# 0.5.0 — release preparation, not published

This minor-version preparation follows NS-07–NS-12. Merge the stacked PRs in order, then this version PR. No Git tag, GitHub Release, website deployment or replacement of existing downloads is performed by these changes.

## Scope and identities

- NS-06 provider-filter parity, adaptive native popover, bounded metadata cache, native/panel history, CSV/JSON exports, opt-in native budgets, safe shared-cache maintenance.
- Root package, plugin and Usage package: `0.5.0`; CLI/MCP/panel/build identities derive from the Usage package. Snapshot schema remains v1 and ccusage stays pinned to 20.0.34.
- `runtime-manifest.json` contains hashes generated by the real two-platform build. Its exact `v0.5.0` asset URLs are **future publication targets, not currently available downloads**. A source checkout needs `npm run build:usage` to provide local runtimes until publication.
- README and website public app links remain on the existing experimental 0.4.3 release. Do not repoint them before a separately approved, verified release.

## Reproduce local artifacts

```sh
npm run build:usage
npm run package:usage
# Run smoke:usage with CODEX_HOME pointing at an isolated synthetic root.
npm test
npm run typecheck:usage
npm run test:usage:browser
npm run test:usage-menubar
npm run validate
npm run build:usage-menubar
npm run smoke:usage-menubar
npm run package:usage-menubar
```

Local outputs (ignored by Git):

- `.artifacts/usage/releases/no-short-usage-darwin-{arm64,x64}.tar.gz`
- `.artifacts/usage-menubar/releases/no-short-usage-menubar-0.5.0-darwin-{arm64,x64}.zip`

These development bundles are ad-hoc signed, **not Developer ID signed or notarized**. Smoke tests execute only the build host's architecture and isolated synthetic sources; Intel compilation/signature/layout checks are not Intel device runtime acceptance. No user installation, login registration, notification permission prompt or actual user-cache deletion is required by this workflow.

## Remaining acceptance / release gates

NS-05 stays in progress: Developer ID signing/notarization, clean-machine installation and Intel runtime checks are still required before claiming those guarantees. Installed-app history/Save dialog flows, live hooks/context, budget permission/banners, sleep/login behavior and VoiceOver also require target-environment acceptance. Browser tests do not prove actual Codex-host file downloads work in every host version.

The metadata-cache benchmark does not demonstrate an end-to-end ccusage speedup. The documented identical-event upstream daily-total undercount remains; no billing, credit/quota or full-contributor attribution guarantee is added. Historical assets stay immutable. Public publication requires separate approval and release verification.
