# No Short Usage 0.7.0 — Experimental (2026-10-27)

Apple Silicon, macOS 14+, ad-hoc signed and not Apple-notarized. App archive: `NoShortUsage-0.7.0-arm64.zip`. This release keeps the existing owner key and canonical signed update channel. Previous release assets remain unchanged. No public Intel native app ZIP is offered.

## What changed

- **Reliable totals (NS-20):** source-built patched ccusage preserves distinct logical sessions across log roots while deduplicating copies within a logical session. Copies with rewritten/ambiguous identities remain a documented limitation.
- **Pricing (NS-16):** inspect pricing source, fetch time and unknown-price coverage. Configure or reset exact provider/model rates locally in the native app; panel/history/export share that basis. An explicit zero rate differs from an unknown price. Historical estimates use the current selected rates, not historical invoices.
- **Comparison (NS-17):** opt into the immediately preceding equal-length calendar range, with provider/model token and estimated-cost changes plus cache-read ratio. Zero baselines and incomplete/old data have explicit states.
- **Session days (NS-18):** choose a day and inspect the sessions that actually contributed within that day. No lifetime-cost ratios or last-activity attribution; inspecting a session preserves pin/follow behavior.
- **Projects and work (NS-13):** group exact contributions using explicit project metadata or recorded Codex parent/child links. Unresolved metadata stays visible; default exports omit raw paths and indirect session identifiers. Claude lineage is not inferred.
- **Anomalies and month scenario (NS-19):** default-off analysis uses the latest seven observed prior days within 30 days, all fully priced. Missing dates are not assumed zero. A large increase uses twice the positive sample median; the month scenario extends the sample mean over remaining days after today. Missing today, insufficient prices/history, stale data or overflow produces insufficient basis. OS notifications require separate opt-in.

## Install or update

Users of 0.6.0 or 0.6.1 can use About/menu → Check for Updates once the 0.7.0 signed feed is deployed, then explicitly confirm Install Update and Install and Relaunch. Users of 0.5.0 or earlier install the new ZIP manually once. Daily discovery remains information-only; it does not download or install silently. The MCP plugin updates separately through its host/plugin workflow.

Verify `SHA256SUMS`, extract the Apple Silicon ZIP and move the app to Applications. The release process does not replace the maintainer's installed app or modify provider logs/preferences.

## Verification and acceptance

`release-validation.json`, `runtime-manifest.json`, the signed appcast and `SHA256SUMS` identify the final artifacts. Release preparation reruns Usage, native/script, browser, website, typecheck and validation checks, rebuilds both runtime architectures and native bundles, and verifies extracted Apple Silicon archive metadata, signatures, pinned key/channel and runtime checksums before publication. Exact results are recorded with the release assets; preparation is not a claim that publication or device acceptance already happened.

The public native app remains Experimental/ad-hoc, not Developer ID signed or notarized. Clean-machine install, Intel execution, real hooks/context, OS permission/banner/login, sleep/wake and VoiceOver are separate NS-05 gates. The previously user-accepted 0.6.0→0.6.1 update does not prove acceptance of 0.7.0. Costs remain API-equivalent estimates, not subscription billing, credits or quotas. Schema v1 and upstream ccusage 20.0.34 remain compatible; the patched runtime must be distributed with these features.
