# No Short Usage 0.6.0 — Experimental (2026-10-26)

Apple Silicon, macOS14+. Public app filename: `NoShortUsage-0.6.0-arm64.zip`. This bootstrap introduces signed, confirmation-only in-app updates (NS-14). App binaries remain ad-hoc signed and are not Apple-notarized; no public Intel native ZIP is offered.

## Installation and future updates

If you have0.5.0 or earlier, download and install0.6.0 manually once. The old app cannot install this bootstrap for you. Quit the old app, extract the ZIP and replace the app in Applications, then open0.6.0. Retain provider logs and preferences.

After that, choose Check for Updates from About or the menu. A newer signed release shows its version and notes; choose Install Update, then Install and Relaunch. Feed/archive signatures are mandatory. The app drains its reader and waits for maintenance before replacement. Cancellation and verification errors retain the current app. There are no automatic background checks/downloads, silent installs, system profiling or release-notes JavaScript.

The canonical ARM feed is `https://no-short.io.vn/updates/experimental-arm64.xml`; its owner public key is tracked in `packages/usage-menubar/update-channel.json` and embedded in the ARM bundle. The private signing key is stored outside the repository with private permissions. Losing that key can require a new manual bootstrap, so the owner must keep a separate secure backup. The MCP plugin is updated separately through its host.

## Verification and release provenance

Root/plugin/Usage identities are0.6.0; snapshot schema remainsv1 and ccusage remains20.0.34. Runtime manifests contain actual rebuilt hashes and exact newv0.6.0 helper URLs. Existing tags and archives are immutable. `release-validation.json` and `SHA256SUMS` identify the exact source and uploaded bytes; the feed is generated from the final signed ARM ZIP and published only after assets are available.

The NS-14 implementation was independently reviewed and tested with real standard Sparkle A→B replacement/relaunch, maintenance drain, preserved synthetic data and eight negative cases. See [local evidence](ns14-local-validation.md). The0.6.0 release is additionally checked as a configured bundle after extraction; private keys and test overrides must not enter the package.

## Remaining NS-05 acceptance

Developer ID/notarization, clean-machine downloaded/quarantined installation, Intel execution, actual OS notification/TCC/login retention, live provider integration and VoiceOver remain separately tracked. Signing update metadata does not provide Apple notarization. Never disable Gatekeeper globally. API-equivalent estimates are not subscription invoices or quota.
