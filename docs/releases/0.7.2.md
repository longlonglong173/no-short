# No Short Usage 0.7.2 — Experimental recovery

These notes describe the 0.7.2 recovery candidate. Preparation, private draft uploads and artifact verification do not establish public availability. Use the published release's assets only after the owner publishes them and public verification succeeds; current status and exact evidence belong in the release PR and GitHub Release. Until then, 0.7.0 remains the temporary verified download for new Apple Silicon installations. Keep an existing 0.7.1 installation while recovery is prepared; do not automatically downgrade.

## What changed

- **Data and partial pricing:** preserve distinct logical sessions across roots while deduplicating copies of the same session. Retain the known cost subtotal when other model prices are unknown/fallback; label the total incomplete. Missing prices never become zero. Costs remain API-equivalent estimates, not subscription charges, invoices, credits or remaining quota.
- **Cache initialization:** concurrent readers can initialize the same cache scope without failing on the other reader's directory creation. Maintenance protection, scan locking and the rule against deleting original provider logs remain in place.
- **Updater packaging:** require the complete pinned Sparkle 2.10.0 framework/resources, nested signatures, production owner public key, signed feed policy and bundled runtime provenance in the final ARM ZIP. The owner key, canonical channel, bundle identity and schema v1 stay unchanged; ccusage remains 20.0.34 with the source-locked reader patches.
- **Release evidence:** freeze the build source before canonical macOS 15 / Xcode 16.4 preparation using Bun 1.3.13 and Rust 1.98.1. The hosted Intel job verifies the same canonical payload's x64 runtime bytes and retains a separate source/run/hash-bound receipt with zero required skips. It does not rebuild a substitute payload.

## Install or recover

After verified assets are public, download `NoShortUsage-0.7.2-arm64.zip` and `SHA256SUMS` from the 0.7.2 GitHub Release. Check the archive's SHA-256 against that release's checksums, extract it, quit the running app, and move **No Short Usage.app** to Applications. Open it in Finder, click the menu bar item, and confirm the running version is **v0.7.2**. Preserve provider logs and preferences; recovery does not require clearing real data or editing installed plugin caches.

- **Updater-less 0.7.1 ZIP:** one manual reinstall of the verified 0.7.2 app is required. An updater absent from the old app cannot retrofit itself. Users of 0.5.0 or earlier also install manually once.
- **Compatible 0.6.0–0.7.0 app with the existing owner key/channel:** after the signed 0.7.2 feed is live, choose About/menu → Check for Updates, review the offered version/notes, then confirm Install Update and Install and Relaunch. Checking remains independent of usage reads; installation drains readers and waits for cache maintenance. Cancellation or verification failure keeps the installed app.
- **Codex MCP plugin:** update separately through the host's supported plugin/marketplace workflow using the complete `no-short-0.7.2.zip` package. Start a new chat afterwards. The app updater updates only the app; installing either product does not install the other.

Quiet daily discovery is information-only. It never silently downloads, opens installer dialogs, installs or sends OS notifications. Manual checks remain available. Do not force a downgrade of the app or its data if recovery fails.

## Artifact evidence and trust limits

The release set includes the ARM app ZIP, complete plugin ZIP, ARM/x64 runtime TARs, `runtime-manifest.json`, `source-provenance.json`, `build-evidence.json`, `candidate.json`, `release-validation.json`, `signed-candidate.json`, `experimental-arm64.xml`, `SHA256SUMS` and standalone `LICENSE`. Use the signed sealed validation's exact public asset allowlist. Source build commit A and later release metadata commit B are recorded externally in the execution ledger and release/PR body; `metadataReleaseCommit` remains null inside sealed validation to avoid a circular self-hash.

Before owner signing, all required canonical CI gates must pass for source A, including the full ARM native suite, both runtime/native builds, extracted actual-artifact negatives and runtime regressions, Linux source/browser/typecheck/website checks, and Intel verification of the same payload. Canonical artifact identity, run/attempt, hashes, toolchains and the original Intel receipt remain distinct evidence. Exact pass counts and final hashes are recorded with the prepared artifacts; these notes do not assert that a pending gate has passed.

The owner signature authenticates the ARM app and its bound ARM runtime hashes. Static x64 manifest matching is not owner-signature authentication, and signed verification does not execute x64. Hosted Intel same-payload execution is mandatory producer evidence, separate from signed ARM validation. Authenticated Intel native distribution remains **M2**; no public Intel native app ZIP is offered.

The public native scope is Apple Silicon (M1 or later), macOS 14+. The app remains **Experimental, ad-hoc signed and not Developer ID signed or Apple-notarized**. macOS can block first launch. Hosted macOS 15 tests do not establish clean-machine/quarantined download acceptance, macOS 14 or physical Intel GUI/device acceptance, real hooks/context, permissions/banners/login behavior, sleep/wake, VoiceOver, interactive performance or the owner's actual 0.7.2 upgrade. Local Xcode 27.1 output is not the canonical production toolchain. The deferred M1 outer performance-runner deadline remains a minor follow-up.

## Publication and rollback policy

Prepare the release as a private draft with **Latest=false**. The owner retains publication and PR merge authority. Publish assets, verify live HTTPS bytes/checksums/signatures, then activate recommendations and the exact signed feed in the approved order. Record the owner's actual upgrade separately before claiming rollout complete. Draft-download verification is not public availability.

If serious live issues emerge, stop recommending/offering the version through reviewed, owner-signed channel changes. Preserve historical assets, never force an app/data downgrade, and prepare the fix under a new increasing version.
