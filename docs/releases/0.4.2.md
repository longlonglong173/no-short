## Scope

The first downloadable product is the independent macOS menu bar app, with
Codex/Claude costs and context rings. It needs macOS 14+. The native interface
is Vietnamese; the website supports English and Vietnamese. The existing Codex
plugin panel and two skills retain their separate installation paths. Installing
the plugin does not install the native app.

The future notarized candidate should contain:

- `no-short-usage-menubar-0.4.2-darwin-arm64.zip`

attribution. Do not attach `.artifacts/usage/releases/no-short-0.4.2.zip` or the

## Prepare locally when credentials exist

Use macOS with Swift 6/Xcode and Bun 1.3.13. Quit the development app before
replacing its bundle. Store Apple notarization credentials using
`xcrun notarytool store-credentials` in your keychain; use a named profile.
See [Apple's notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow).

```sh
bun install --cwd packages/usage --frozen-lockfile
export NO_SHORT_SIGN_IDENTITY='Developer ID Application: YOUR VERIFIED IDENTITY'
export NO_SHORT_APPLE_TEAM_ID='YOURTEAMID'
export NO_SHORT_NOTARY_PROFILE='YOUR_KEYCHAIN_PROFILE'
npm run build:usage
npm run test:usage-menubar
npm run build:usage-menubar
npm run smoke:usage-menubar
npm run release:usage-menubar
```

The final command refuses ad-hoc/Development identities, wrong teams, missing
hardened runtime or timestamps before sending either app to Apple. It staples
accepted apps, creates ZIPs, extracts them again, and verifies restored signatures,
tickets and Gatekeeper assessment. Verified output is under
`.artifacts/usage-menubar/distribution/`. It does not upload a GitHub release.
Ordinary `package:usage-menubar` remains a local development ZIP command.

## Optional GitHub preparation

After merging the workflow to `main`, configure environment `macos-release`
with owner reviewers/protection as appropriate. Its variables:

| Variable | Value |
| --- | --- |
| `MACOS_SIGN_IDENTITY` | Exact Developer ID Application identity, or certificate SHA-1 |
| `APPLE_TEAM_ID` | Expected 10-character Apple team ID |

Set these secrets privately in GitHub Settings → Environments:

| Secret | Purpose |
| --- | --- |
| `MACOS_CERTIFICATE_BASE64` | Certificate/private key exported as PKCS#12, base64 |
| `MACOS_CERTIFICATE_PASSWORD` | PKCS#12 password |
| `APPLE_NOTARY_KEY` | App Store Connect API private key contents |
| `APPLE_NOTARY_KEY_ID` | API key ID |
| `APPLE_NOTARY_ISSUER_ID` | API issuer ID |

Manually run **Prepare notarized macOS release** from `main`. It validates/tests
first, uses a temporary keychain, builds both architectures and invokes the same
release verifier. Key material is removed by an always-run cleanup step. It
uploads an Actions artifact only after all checks pass. It has read-only
repository permissions, no tag trigger and no GitHub publishing step. Apple
receives the app only when a maintainer explicitly runs preparation.

## Draft public release notes

No Short Usage brings local Codex and Claude Code usage estimates to the macOS
menu bar. Choose or pin a session, inspect token/cost totals and a seven-day
chart, and see context occupancy around each provider logo. Claude context and
automatic tracking are opt-in; existing custom status lines are preserved.

Requires macOS 14+. Choose arm64 for Apple Silicon or x64 for Intel. Verify
SHA256SUMS, extract the ZIP, move the app into Applications and open it. No DMG,
runtime installation or API key is required. Usage estimates are API-equivalent
costs, not subscription bills, credits or quotas. Context is a latest-recorded
estimate. Read the setup/privacy guide before connecting hooks.
