# Privacy Policy for no-short

Effective date: October 20, 2026

`no-short` provides No Short Usage: a native macOS menu bar app and an optional local Codex usage panel. It does not operate a developer-hosted data collection backend, use tracking cookies, or send user data to the developer.

When enabled, the local MCP helper reads retained Codex logs and the session-name index, plus Claude Code logs only when Claude roots are explicitly configured. ccusage computes token usage and estimated API-equivalent cost. A local cache stores session names/IDs, tokens, models, dates and estimates, not prompts or messages. Session titles can still be private. Neither the helper nor the panel modifies source logs.

Online pricing scans may download public model prices from LiteLLM. Source-only installation may download pinned executables from this repository's GitHub release. These services receive normal network request metadata; no log, prompt or session title is included. The launcher verifies SHA-256 before running downloaded executables. Full packages bundle the runtime.

Choosing Check for Updates in the native app sends an unauthenticated request to GitHub’s public releases API. It contains no logs, session metadata, API keys or account credentials. GitHub receives ordinary request metadata, such as IP address and the app’s User-Agent. The request uses an ephemeral session without cookie, credential or disk-cache storage. There are no automatic update checks, downloads or app replacement. Opening release notes uses your browser and GitHub’s own policy.

Opening or requesting usage through the MCP plugin makes results available to the ChatGPT/Codex host. The selected session's title/ID, provider (when available), token counts, model names, dates and cost estimates, along with session count and period totals, are returned in structured tool results and may enter model context. The complete session list is supplied to the widget through MCP metadata, rather than model context. This is not a guarantee that all data stays on your device: the host processes these results under its own terms, privacy policy, account settings and retention rules. No account token, cookie, OpenAI API key or billing credential is extracted. The standalone menu bar app does not send its usage snapshots to ChatGPT/Codex through MCP.

The NS-06 panel source stores its provider filter and pinned session ID together in browser local storage (`no-short-usage-selection-v1`) and host widget state where supported. Filtering acts on the existing snapshot and does not send a separate provider-filter request. MCP summaries name their configured providers; hiding a provider in the panel does not remove that provider's data from metadata or combined tool-result totals.

Caches are stored in `~/Library/Caches/no-short/usage` (or a configured location). Usage snapshots persist until replaced or manually deleted; there is no automatic maximum retention period for these cache files. After stopping the plugin and companion app, you can delete this directory to remove cached session titles/IDs and usage. Downloaded runtimes are stored separately in `~/Library/Caches/no-short/runtime`. Deleting local caches does not remove results already supplied to the host; manage those through the host's chat and data controls. Removing the plugin does not remove Codex logs. Hidden/closed panels stop polling; no separate daemon is installed by the plugin.

The optional No Short Usage menu bar companion reads retained local Codex and Claude Code logs through the bundled usage engine. It checks the default Claude directories (`~/.config/claude` and `~/.claude`), an inherited `CLAUDE_CONFIG_DIR`, or the selected Claude source; a missing installation contributes no usage. It refreshes every 15 seconds while running and coalesces log/activity changes into additional refreshes, including when Codex panels are closed. Scanning stops on quit or sleep. It uses the same local cache mechanism, scoped to its sources, and may fetch public model pricing from LiteLLM; no log contents, prompts or session titles are sent to the pricing provider. It adds no telemetry or developer-hosted backend. Local session names and usage can be visible in the menu and its tooltips.

Setup-guide dismissal, source-folder paths, provider selection, pinned session ID, last handled submission timestamp and hook-configuration preference are saved locally in the `dev.noshort.usage.menubar` UserDefaults domain. Opening at login is opt-in through macOS and does not install a separate daemon.

Connecting automatic chat tracking is opt-in. It adds owned command hooks to Codex `hooks.json` and Claude Code `settings.json` under the hosts' configured home directories, preserving other settings and saving an existing file as `.no-short-backup` before its first change. These backups may contain private host settings. Hook input is reduced to provider, session ID, optional turn ID, event type and timestamp; prompts, responses, working directories and transcript paths are not stored. Records are saved under `~/Library/Application Support/no-short/usage/activity` (or `NO_SHORT_USAGE_ACTIVITY_DIR`) with private directory/file permissions. Approximately 512 records are retained; only events from the last 24 hours drive automatic following. Connection diagnostics may display the timestamp of an older retained event without marking it active.

The context-ring feature reads a bounded tail of the selected Codex log locally and retains only numeric context occupancy for display. Claude context collection is separately opt-in through an owned status-line command; an existing custom status line is not overwritten. The collector stores only session ID, used/limit values and timestamp in `~/Library/Application Support/no-short/usage/context` (or `NO_SHORT_USAGE_CONTEXT_DIR`), with directory/file permissions 0700/0600. It does not store incoming prompts, responses, transcript paths, model payloads or working directories. Setup saves an existing settings file as `.no-short-context-backup`; this backup may contain private host settings. Disconnecting removes only the owned status-line setting and leaves records and backups for the user to remove separately. After each write, cleanup retains the current session and up to 511 other recent context files; evicted sessions display unknown until they report again. Context files are local and are not sent to the developer or a pricing service.

Before deleting the companion, use its settings to remove tracking hooks, disconnect Claude context and disable opening at login. Hook removal leaves other handlers and backups intact. Deleting the app does not delete logs, cache, activity records, host backups or UserDefaults preferences; these local files/preferences can be removed separately after stopping the app and plugin.

Reusable writing and reporting skills are maintained separately in `no-short-skills`, with their own privacy policy: https://github.com/longlonglong173/no-short-skills/blob/main/PRIVACY.md.

If you contact the project through a GitHub issue, the information you choose to include is processed by GitHub and may be visible according to that repository's settings. Do not include secrets or sensitive personal information in an issue.

For privacy questions or requests, open an issue at https://github.com/longlonglong173/no-short/issues.

## Unreleased source: history, export, budgets and cache maintenance

Optional daily history preserves provider/model/token/price aggregates from retained local logs. MCP history is widget metadata, not expanded into model-visible structured summaries; the host can still process metadata under its own terms. History filters do not read additional logs or change the pinned session.

CSV/JSON export occurs only on an explicit save/download action. Files contain the selected range/provider/timezone and price uncertainty, not messages or log paths. Session names/IDs are excluded by default; an explicit opt-in adds separate last-activity-in-range references, not lifetime usage attribution. Embedded panel downloads use the host capability and its consent/denial flow; development preview uses browser downloads. Exported files and already supplied host results are not removed by cache clearing.

Native budgets and notification preferences are stored locally, disabled by default. Dedup state uses hashed source keys; budget notifications contain provider/period estimates, not session titles or messages. Budget permission requests require explicit notification opt-in; existing context controls remain independent.

The native Data management window can clear recognized generated snapshot/metadata/marker files in the default shared usage-cache scopes after confirmation. It drains the companion reader and coordinates new MCP readers with a root maintenance guard; active scans block deletion. Symlinks, source overlap and custom cache paths are refused; unknown files and original logs/preferences/backups/configuration are retained. Only empty generated directories are removed. Older runtimes should be closed before maintenance. Clearing cache does not reset usage or bills: statistics are rebuilt from retained logs. It does not remove downloaded runtimes, global third-party pricing caches, exports, UserDefaults, activity records or host-held data. Live installed-app confirmation and external-host acceptance are separate from local fixture tests.

Native guard mutation/recovery is serialized by a kernel lock on the permanent empty `.maintenance-recovery.lock` file, which is retained to keep one lock inode. New TS readers do not delete guards; stable abandoned guards can be ignored for reading after grace and are physically reclaimed only by native maintenance.
